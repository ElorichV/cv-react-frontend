# CV React Frontend

> [Español](README.es.md)

Single Page Application (SPA) developed to showcase a dynamic professional portfolio. Consumes an external .NET API and is optimized for performance and security in the cloud.

- **Core**: React 18+, TypeScript, Vite
- **Styling**: Tailwind CSS + React Icons
- **Communication**: Axios (HTTP Client)
- **Infrastructure**: AWS S3 (Static Hosting) + AWS CloudFront (CDN & SSL)

## ☁️ AWS Deployment Architecture
The deployment uses a Serverless Frontend architecture:

**AWS S3**: Acts as the origin server, storing static files (HTML, CSS, JS) generated by the build command.

**AWS CloudFront**: Acts as the global distribution layer.
- Provides SSL/TLS certificate (HTTPS) that S3 doesn't have natively.
- Acts as Reverse Proxy to unify Frontend and Backend under the same domain.

### CloudFront "Bridge" Configuration
To solve modern security issues, CloudFront was configured with two origins:

- **Default Origin (*)**: Points to S3 bucket. Serves the website.
- **API Origin (/api/*)**: Points to Elastic Beanstalk environment.

**Behavior**: Any request to https://mydomain.net/api/* is internally redirected to the .NET HTTP server.

**Benefit**: The browser only sees HTTPS, eliminating "Mixed Content" errors.

## 🔧 Troubleshooting Log
During the construction of this frontend, we overcame the following technical obstacles:

### 1. Critical Error: "Mixed Content" (Security Block)
**Problem**: The site loaded on HTTPS (CloudFront), but tried to make requests to the API that was on HTTP (Elastic Beanstalk). Browsers block this automatically.

**Solution**: A Behavior was implemented in CloudFront.
- A new origin pointing to the Elastic Beanstalk API was created.
- The /api/* path was configured to redirect traffic to that origin.
- React code (App.tsx) was updated to call the API using CloudFront's relative/secure URL.

### 2. Gateway Error: "504 Gateway Timeout" in CloudFront
**Problem**: CloudFront tried to connect with the S3 bucket using HTTPS, but S3's "Website Hosting" mode only supports HTTP. The connection failed due to timeout.

**Solution**: The "Origin Protocol Policy" configuration in CloudFront was changed to "HTTP Only". This allows CloudFront to talk to S3 in HTTP (internal), but serve the end user in HTTPS (secure).

### 3. Local Environment Conflict: "npm/nvm not recognized"
**Problem**: Conflict between a native Node.js installation and NVM (Node Version Manager), plus using CMD that didn't load environment variables correctly.

**Solution**: Complete uninstallation of Node/NVM, clean reinstallation of NVM, use of PowerShell and explicit activation with nvm use 20.

### 4. Structure Error: Dependencies in root folder
**Problem**: npm install was executed in the wrong folder (C:\Proyectos), creating node_modules outside the project.

**Solution**: Manual cleanup of files and reinstallation of dependencies within the correct cv-react-frontend folder.

### 5. Updates not reflected (Persistent cache)
**Problem**: When uploading changes to S3 (like the API URL correction), the live site continued showing the old version due to aggressive CDN caching.

**Solution**: An Invalidation was executed in CloudFront with the /* path to purge the global cache and force download of new files.

## 📁 Code Structure (src/)

### Modular Architecture
The project was refactored from a monolith to a modular component architecture:

- **App.tsx**: Main component that manages global state, consumes the API and orchestrates all modules.
- **components/**: Folder with specialized components:
  - `Header.tsx`: Personal information and social links
  - `About.tsx`: Professional summary
  - `Experience.tsx`: Work history
  - `Projects.tsx`: Project portfolio
  - `Skills.tsx`: Technical skills organized by categories
  - `Education.tsx`: Academic background and certifications
  - `Hobbies.tsx`: Personal interests
  - `Footer.tsx`: Footer

### Configuration
- **tailwind.config.js**: Custom brand configuration (background, card, accent colors)
- **App.css / index.css**: Tailwind base directives

## 🔗 Backend Integration

The frontend consumes a single master endpoint that returns the entire portfolio structure:

### Dual URL Configuration
```typescript
// LOCAL MODE (Development)
axios.get('https://localhost:7081/api/Profile')

// PRODUCTION MODE (Build)
axios.get('https://d1xk37jjpjmwph.cloudfront.net/api/Profile')
```

### TypeScript Interfaces
The project defines strict interfaces to ensure consistency with the API:
- `UserProfile`: Main profile structure
- `WorkExperience`: Work history
- `Project`: Portfolio projects
- `Skill`: Technical skills
- `EducationItem`: Academic background
- `Certification`: Certifications
- `Hobby`: Personal interests
- `Link`: Social/professional links

**Benefit**: Secure call through CloudFront proxy, avoiding "Mixed Content" errors and unifying Frontend/Backend under HTTPS.
